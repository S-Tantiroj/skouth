# ขั้นตอนและวิธีการดำเนินงาน

## 3.1 ขั้นตอนการรวบรวมข้อมูล

### 3.1.1 ข้อมูลที่ระบบต้องการ

ก่อนเลือกแหล่งข้อมูล คณะผู้จัดทำกำหนดว่าข้อมูลผู้สมัครแต่ละรายต้องมีอะไรบ้าง
โดยพิจารณาจากสิ่งที่ส่วนต่าง ๆ ของระบบต้องใช้จริง

| ข้อมูล | ใช้ทำอะไรในระบบ | ผลเมื่อขาด |
|---|---|---|
| ชื่อ · ลิงก์โปรไฟล์ | ระบุตัวบุคคล และใช้ตรวจข้อมูลซ้ำ | ตรวจข้อมูลซ้ำได้เพียงจากชื่อ ซึ่งคลาดเคลื่อนได้ |
| ตำแหน่งปัจจุบัน (Headline) · สรุปโปรไฟล์ · ทักษะ | ประกอบเป็นข้อความสำหรับสร้างเวกเตอร์ความหมาย | เวกเตอร์มีความหมายน้อยลง การจัดอันดับแม่นยำน้อยลง |
| ประวัติการศึกษา พร้อมชื่อสถาบัน | ตัดสินว่าสำเร็จการศึกษาจากต่างประเทศหรือไม่ · ตัวกรองสาขาและระดับการศึกษา | ระบุกลุ่มเป้าหมายของโครงงานไม่ได้ |
| ประวัติการทำงาน **พร้อมช่วงเวลา** | คำนวณจำนวนปีประสบการณ์ | ผู้สมัครถูกนับเป็นประสบการณ์ศูนย์ปี และหลุดจากตัวกรองประสบการณ์ขั้นต่ำทุกครั้ง |

ข้อมูลส่วนที่สำคัญที่สุดและหาได้ยากที่สุดคือ**ช่วงเวลาของประวัติการทำงาน** และ
**ชื่อสถาบันการศึกษาครบทุกรายการ** ซึ่งเป็นเกณฑ์ที่ใช้เปรียบเทียบแหล่งข้อมูลในหัวข้อถัดไป

### 3.1.2 การทดลองใช้และเปรียบเทียบเครื่องมือดึงข้อมูล

ชื่อโครงงานกำหนดให้ใช้ข้อมูลจาก LinkedIn แต่ LinkedIn API ไม่เปิดให้เข้าถึงข้อมูล
โปรไฟล์ของบุคคลอื่นเพื่อการสรรหาบุคลากรโดยทั่วไป คณะผู้จัดทำจึงทดลองและเปรียบเทียบ
เครื่องมือดึงข้อมูลทางเลือก โดยกำหนดเงื่อนไขไว้สามข้อ คือ **ไม่มีค่าใช้จ่าย ·
ทำงานอัตโนมัติได้ · ได้ข้อมูลครบตามหัวข้อ 3.1.1**

ตารางที่ 3-1 ผลการเปรียบเทียบเครื่องมือดึงข้อมูล

| เครื่องมือ | วิธีเข้าถึงข้อมูล | ผลการทดลอง | ค่าใช้จ่าย | ผล |
|---|---|---|---|---|
| **PhantomBuster** | ใช้เซสชันของบัญชี LinkedIn ที่ลงชื่อเข้าใช้ | ค้นหาด้วยบัญชีใหม่ได้ผลเป็น "LinkedIn Member" ทั้งหน้า ไม่มีชื่อและลิงก์ เพราะแพลตฟอร์มจำกัดการมองเห็นตามเครือข่ายของบัญชี | รายเดือน | ไม่ผ่าน |
| **joeyism/linkedin_scraper** (โอเพนซอร์ส) | ใช้เซสชันของบัญชี LinkedIn ที่ลงชื่อเข้าใช้ | ตรวจจากซอร์สโค้ด ได้ช่วงเวลาการทำงานครบ แต่**ค้นหาบุคคลใหม่ไม่ได้** ต้องรู้ลิงก์โปรไฟล์อยู่แล้ว และไม่มีข้อมูลทักษะ | ไม่มี | ไม่ผ่าน |
| **Bright Data** (ดึงจากลิงก์) | ดึงจากหน้าสาธารณะโดยไม่ลงชื่อเข้าใช้ | ทดลอง 5 รายการ รายงานผลสำเร็จร้อยละ 100 แต่**ประวัติการทำงานว่างทุกรายการ** และมีชื่อสถาบันเฉพาะรายการการศึกษาแรก | โควตาฟรี | ไม่ผ่าน |
| **Bright Data** (ค้นหาบุคคล) | ค้นจากหน้าผลการค้นหาสาธารณะ | **รับเงื่อนไขเป็นชื่อบุคคลเท่านั้น** ค้นด้วยตำแหน่งงานหรือสถาบันไม่ได้ ผลที่ได้เป็นข้อความที่ถูกตัดทอน | โควตาฟรี | ไม่ผ่าน |
| **Bright Data** (ชุดข้อมูลสำเร็จรูป) | ซื้อชุดข้อมูลที่กรองด้วยเงื่อนไขได้ | ไม่ได้ทดลอง | ขั้นต่ำ 250 ดอลลาร์สหรัฐ | เกินงบประมาณ |
| **X-ray Search** ผ่าน Google | ค้นหน้าโปรไฟล์ผ่านดัชนีของเครื่องมือค้นหา | แสดงชื่อและลิงก์ได้ทุกรายการ มีบริษัทและสถาบันในตัวอย่างข้อความ แต่**ไม่มีช่วงเวลา** และข้อความไม่มีโครงสร้าง | ไม่มี | ใช้ได้แบบกึ่งอัตโนมัติ |

ผลการเปรียบเทียบพบว่า**ไม่มีเครื่องมือใดผ่านเงื่อนไขทั้งสามข้อพร้อมกัน**
เครื่องมือที่ได้ข้อมูลครบต้องลงชื่อเข้าใช้ด้วยบัญชีผู้ใช้จริง ซึ่งขัดกับข้อกำหนด
การใช้งานของแพลตฟอร์มและเสี่ยงต่อการถูกระงับบัญชี เครื่องมือที่ไม่ต้องลงชื่อเข้าใช้
ได้ข้อมูลไม่ครบในส่วนที่ระบบต้องใช้ และบริการที่ทั้งครบและไม่ต้องลงชื่อเข้าใช้
มีค่าใช้จ่ายเกินขอบเขตของโครงงาน นอกจากนี้ช่องทางเรียกใช้เครื่องมือค้นหาผ่าน
โปรแกรมก็ปิดตัวลงทั้งสองราย โดย Google Custom Search JSON API ปิดรับลูกค้าใหม่
และมีกำหนดยุติบริการวันที่ 1 มกราคม 2570 ส่วน Bing Search API ยุติบริการไปแล้ว
เมื่อวันที่ 11 สิงหาคม 2568

ผลการทดลองที่น่าสังเกตคือ **บริการที่รายงานผลสำเร็จร้อยละ 100 ยังคืนข้อมูลที่ขาด
ส่วนสำคัญได้** และการได้ชื่อสถาบันเพียงรายการแรกอันตรายกว่าการไม่ได้ข้อมูลเลย
เพราะระบบจะตัดสินว่าผู้สมัครไม่ได้จบจากต่างประเทศทั้งที่อาจมีปริญญาต่างประเทศ
อยู่ในรายการที่ไม่มีชื่อ การตรวจผลจึงต้องดูความครบของแต่ละฟิลด์ ไม่ใช่อัตราความสำเร็จ

### 3.1.3 แหล่งข้อมูลที่เลือกใช้

จากผลการเปรียบเทียบ ระบบเวอร์ชันนี้รวบรวมข้อมูลผ่านสามช่องทาง

1. **การนำเข้าไฟล์ CSV** — ผู้จัดการข้อมูลอัปโหลดไฟล์ผ่านหน้าเว็บ ระบบรองรับ
   รูปแบบไฟล์ผลลัพธ์ของ PhantomBuster ทั้งสองชนิด และแบบไฟล์ (Template) ที่ระบบ
   จัดเตรียมให้ ซึ่งทดสอบแล้วว่าตัวอ่านไฟล์ของระบบอ่านได้ครบทุกคอลัมน์
2. **X-ray Search เป็นเครื่องมือช่วยค้นหา** — ระบบสร้างคำค้นจากเงื่อนไขที่ผู้ใช้
   กรอก เช่น ตำแหน่งงานและสถาบัน ให้ผู้ใช้เปิดผลการค้นหาเอง แล้วกรอกข้อมูลลงแบบไฟล์
   ก่อนนำเข้า ระบบไม่ดึงผลการค้นหาโดยอัตโนมัติ
3. **การประเมินโปรไฟล์ของตนเอง** — ผู้ใช้อัปโหลดประวัติย่อของตนเอง ซึ่งเป็นข้อมูล
   ที่ครบที่สุดเพราะเจ้าของข้อมูลจัดทำเอง แต่จัดเก็บแยกจากฐานข้อมูลผู้สมัคร
   และไม่นำไปใช้ในการค้นหาของฝ่ายบุคคล

นอกจากนี้ ระหว่างการพัฒนาและทดสอบ ระบบใช้**ข้อมูลสังเคราะห์** (Synthetic Data)
ที่สร้างขึ้นด้วยแบบจำลองภาษา โดยระบุแหล่งที่มาเป็น `synthetic` แยกจากข้อมูลจริง
เพื่อไม่ต้องใช้ข้อมูลส่วนบุคคลของบุคคลจริงในการทดสอบ

ส่วนการดึงข้อมูลอัตโนมัติตามกำหนดเวลา ระบบได้พัฒนาชุดคำสั่งและโครงสร้างรองรับไว้
ครบแล้ว ได้แก่ ตารางบันทึกรอบการนำเข้า คิวรอการตรวจสอบ และรายชื่อผู้ขอระงับ
**แต่ยังไม่เปิดใช้งาน** จนกว่าจะมีแหล่งข้อมูลที่ผ่านเงื่อนไขในหัวข้อ 3.1.2

### 3.1.4 ขั้นตอนการนำเข้าข้อมูล

1. ผู้จัดการข้อมูลเลือกไฟล์และชนิดของไฟล์ที่หน้านำเข้าข้อมูล
2. ระบบตรวจสิทธิ์**ก่อน**อ่านไฟล์
3. ระบบอ่านไฟล์ จับคู่ชื่อคอลัมน์ และทำความสะอาดข้อมูล เช่น ตัดช่องว่างเกิน
   แปลงอักขระพิเศษ และคำนวณจำนวนปีประสบการณ์จากช่วงเวลาทำงาน
4. ระบบตรวจทีละรายการว่าอยู่ในรายชื่อผู้ขอระงับหรือไม่ ถ้าอยู่จะข้ามโดยไม่ส่ง
   ข้อมูลออกไปประมวลผลภายนอก
5. ระบบสร้างเวกเตอร์ความหมาย แล้วตรวจข้อมูลซ้ำด้วยลิงก์โปรไฟล์และชื่อ
   ถ้ามีอยู่แล้วจะปรับปรุงข้อมูลเดิม ถ้ายังไม่มีจะเพิ่มใหม่
6. ระบบบันทึกกิจกรรมการนำเข้า และแสดงจำนวนรายการที่เพิ่ม ปรับปรุง ข้าม และผิดพลาด

### 3.3.1 การเข้าสู่ระบบและการอนุมัติบัญชี

บัญชีที่สมัครใหม่อยู่ในสถานะรออนุมัติตั้งแต่สมัคร ผู้ใช้ต้องยืนยันอีเมลและได้รับอนุมัติจาก
ผู้ดูแลระบบทั้งสองอย่างจึงจะเข้าใช้งานได้ เมื่อเข้าสู่ระบบ ระบบยืนยันตัวตนแล้วอ่านบทบาทและสถานะของบัญชี
**การยืนยันตัวตนสำเร็จยังไม่เพียงพอ** บัญชีต้องมีสถานะอนุมัติจึงจะเข้าใช้งานได้
และหากอ่านข้อมูลบัญชีไม่ได้ ระบบจะไม่อนุญาตให้เข้าใช้งาน

### 3.3.3 การค้นหาและคัดกรองผู้สมัคร

|---|---|

| Next.js บน Vercel | สร้างหน้าเว็บ ตรวจการเข้าสู่ระบบ และให้บริการ API ของระบบ |

### 3.6.2 กระบวนการหลักของระบบ

ระบบมีกระบวนการหลักสามส่วนที่ต่อเนื่องกัน

1. **การนำข้อมูลเข้า** — ข้อมูลผู้สมัครจากไฟล์ถูกทำความสะอาด สร้างเวกเตอร์ความหมาย
   และจัดเก็บ ส่วนตำแหน่งงานถูกสร้างเวกเตอร์ด้วยแบบจำลองเดียวกันเมื่อบันทึก
   ทั้งสองจึงอยู่ในปริภูมิเวกเตอร์เดียวกัน
2. **การค้นคืน** — คำค้นหาหรือตำแหน่งงานถูกเปรียบเทียบกับเวกเตอร์ของผู้สมัคร
   ในฐานข้อมูล โดยกรองเงื่อนไขก่อนแล้วจึงจัดอันดับ **ขั้นนี้ไม่เรียกแบบจำลองภาษา**
   ยกเว้นการสกัดเงื่อนไขจากคำค้นหาหนึ่งครั้ง
3. **การประเมิน** — เมื่อผู้ใช้เลือกผู้สมัครรายหนึ่ง ระบบส่งข้อมูลพร้อมความต้องการ
   ของตำแหน่งงานให้แบบจำลองภาษา แล้วเก็บผลไว้ใช้ซ้ำ

การแยกการค้นคืนออกจากการประเมินทำให้จำนวนครั้งที่เรียกแบบจำลองภาษาไม่เพิ่มตาม
จำนวนผลการค้นหา ซึ่งจำเป็นต่อการทำงานภายใต้บริการแบบไม่มีค่าใช้จ่าย

### 3.6.3 เส้นทางการเข้าถึงข้อมูล

หน้าเว็บเข้าถึงฐานข้อมูลได้สองเส้นทาง

| เส้นทาง | ใช้กับ | ด่านควบคุมการเข้าถึง |
|---|---|---|
| ผ่าน API ของระบบ | การค้นหา การประเมิน การนำเข้า การจัดการตำแหน่งงานและผู้ใช้ | API ตรวจสิทธิ์ก่อนทำงาน และกรองข้อมูลตามเจ้าของในคำสั่งเอง |
| ตรงไปยังฐานข้อมูลด้วยคีย์สาธารณะ | การเข้าสู่ระบบ Shortlist และการตั้งค่าส่วนตัว | การควบคุมสิทธิ์ระดับแถวและระดับคอลัมน์ในฐานข้อมูล |

คีย์สาธารณะถูกฝังอยู่ในหน้าเว็บจึงเป็นความลับไม่ได้ **ความปลอดภัยของเส้นทางที่สอง
จึงอยู่ที่ฐานข้อมูลทั้งหมด** ไม่ใช่ที่หน้าจอ ตัวอย่างเช่น ผู้ใช้แก้ไขได้เฉพาะชื่อที่แสดง
และการตั้งค่าของตนเอง ส่วนบทบาทและสถานะบัญชีแก้ได้ผ่าน API ของผู้ดูแลระบบเท่านั้น
ในทางกลับกัน เส้นทางแรกใช้กุญแจที่ข้ามการควบคุมระดับแถว การกรองตามเจ้าของข้อมูล
ในคำสั่งของ API จึงเป็นตัวควบคุมการเข้าถึงโดยตรง
